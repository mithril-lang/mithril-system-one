# Source-bound terms review 0.1.0

This runtime consumes supplied UTF-8 text, not URLs or credentials. Each service has a name, plan, jurisdiction and optional usage description. Supply terms, privacy, pricing, cancellation and DPA as applicable (one of each, maximum five). Each document needs `kind`, public provenance `url` (HTTPS without credentials/query/fragment), UTC `retrievedAt`, declared `language` (`ja`, `en`, `other`), `text`, and the exact UTF-8 `sha256`; optional `effectiveDate` is YYYY-MM-DD. Unavailable information is `unknown`, never inferred from service name. Documents can contain private material: outputs are private too.

`node bin/mithril-terms-review.mjs --stdin` accepts one service. `--workflow` accepts `{ "tasks": [ ... ] }`, maximum three services; a refusal stops the run and emits no partial report. No external I/O, inference or credentials. The Hermes adapter registers `mithril_terms_review` for a separately configured owning profile.

Rules identify bounded JA/EN review candidates for renewal, refund, data sharing, AI training, content licences, unilateral changes, termination, liability, dispute resolution and portability. A match includes source hash, line and UTF-16 start/end offsets into the exact supplied text. No clause text is copied into output. Negation, exceptions, favorable language and cross-line clauses require full contextual review; missing matches never prove absence or safety. Unsupported languages explicitly remain unknown.

An agent or human can supply up to 50 `assessments`: `dimension` (billing-exit/data-control/fairness/user-choice/transparency), `risk` (low/medium/high/unknown), `rationale`, `sourceSha256`, `start`, `end`. The runtime validates the source span, not the truth of the interpretation. Results label these reviewer-supplied and not independently verified. Risk depends on actual usage, plan and jurisdiction. No aggregate honesty score, enforceability claim or company accusation is generated. Operational practice always requires separate evidence.

Optional `previous` documents produce hash-bound version changes and added/removed rule signals. A changed document remains changed even if its rule signals are identical. This is comparison, not scheduled monitoring; missing baselines and documents are explicit. The operator schedules runs separately with authorized sources and retained private baselines.

Workflow: private inventory → verify applicability/source → import and hash complete documents → contextual review → version comparison → owner review → separately prepare a public Knowledge summary. Inventory, account IDs, negotiated prices, contract text and receipts are never automatically published. Public summaries require a concrete reviewed payload and public destination; do not send private documents to Knowledge. This release publishes its methodology and integration guide, not anyone's subscription inventory or vendor ratings.

The JSON report is an importable record (`mithril-terms-review-v1`); retain locally or in an explicitly selected account-bound private workspace. SHA-256 proves byte identity only, not origin authenticity or signature. Acquisition, OCR/PDF extraction, applicability verification, scheduled execution, Knowledge contribution submission and installed Desktop/model qualification are separate capabilities.
