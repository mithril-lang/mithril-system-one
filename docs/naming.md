# System One Coding and Mithril Semantic Loop

System One Coding is the public name of the Mithril-specific development method. Mithril Semantic Loop names the agent execution loop used to produce and check supported Mithril artifacts.

| Role | Canonical wording |
| --- | --- |
| Development method and primary headline | **System One Coding** |
| Agent loop | **Mithril Semantic Loop** |
| Technical descriptor | **Ontology-driven generation and verification** |
| Brand attribution when needed | **Mithril System One Coding** |

## Public introduction

**System One Coding — Generate Mithril code, verify its meaning, and iterate through a semantic loop.**

System One Coding uses bounded proposals and Mithril's compiler and ontology checks to create inspectable artifacts. The Mithril Semantic Loop grounds supported tasks in their requirements and ontology, proposes or constructs a candidate, compiles and validates it, and records the checked result. Repair or refactor steps are available only where the executor's supported task contract permits them.

“Verify its meaning” means checking the declared ontology, constraints and task contract. It is not a claim of unrestricted understanding, complete requirement coverage or general software correctness. A loop does not imply repeated model calls: the current task harness bounds model proposals per task and stops on failure or unknown outcomes.

## Usage

Use System One Coding for product introductions, demonstration titles and development-method explanations. Use Mithril Semantic Loop for the execution architecture and agent-loop explanation. Use ontology-driven generation and verification as the technical descriptor, rather than presenting System One Semantic Coding or System One Ontologic Coding as competing product names.

Existing repository names, CLI methods such as `system-one` and `ontology`, tool IDs, artifact formats and immutable Registry pins retain their compatibility meaning. This naming policy does not migrate them or qualify a new runtime. Keep historical measurements and quoted source evidence unchanged; describe supported scope, timing boundaries, failures and unknown billed cost alongside performance claims.
