# Mithril-language pilot — 2026-10-07 JST

Three public static-document fixtures passed through both model arms and the template control. The observed median was **5.760 seconds for System One** and **15.833 seconds for full-source generation**. These are narrow pilot observations, not general coding performance or measured savings.

| Method | Passed | Median seconds | Maximum seconds | Total input tokens | Total output tokens | Billed cost |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| System One, five-field proposal | 3/3 | 5.760 | 6.550 | 573 | 189 | Unknown |
| Same Qwen, full Mithril source | 3/3 | 15.833 | 16.009 | 2,013 | 1,480 | Unknown |
| Known-field template, no inference | 3/3 | 0.131 | 0.150 | 0 | 0 | Infrastructure unknown |

## Conditions

- Existing public fixtures `static-01` through `static-03`: report, dashboard and directory, with exact known content. One attempt per method/task; order rotated. No retry or repair.
- Both model arms: `https://api.mithril.fund/v1/chat/completions`, `qwen/qwen3.8-27b`, temperature 0, completion limit 2,048. No OpenRouter calls.
- Same starter/catalog, actual `https://app.mithril.fund/api/compile`, admission and content checks. Each task produced matching graph digests across all three arms.
- Six inference requests and nine compiler requests in total. Every attempt is included; no failed or unknown outcomes occurred.
- Time covers dispatch through source emission, real compilation and task validation. It excludes Chat, human review and GitHub publication. Requests were sequential from a macOS client using Node 26.7.0; network and service conditions were not controlled.
- The response omitted `usage.cost`. Provider-reported and settled billed costs remain null. Token counts do not establish actual monetary savings, and no price was guessed.
- Benchmark implementation pinned to [457cd4605140dc3a2580b3d51487b95f55b36b65](https://github.com/mithril-lang/mithril-system-one/tree/457cd4605140dc3a2580b3d51487b95f55b36b65).

## What this supports

A short structured proposal can reduce emitted source and observed latency against this full-source baseline while preserving the exact task contract. This is representation engineering on bounded tasks: the optional `llm-fields` arm uses the same implementation as System One and was not run. The known-field template is faster still and requires no model. These public parameterization fixtures are not held-out software-engineering tasks; three single trials do not establish tail latency, production reliability, or superiority over optimized LLM systems.

Jev was not invoked in this pilot. Its separate [historical comparison](jev-comparison.md) uses a different task and verifier; it must not be merged into this table.
