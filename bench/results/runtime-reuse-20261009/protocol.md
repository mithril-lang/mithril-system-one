# Local compiler reuse experiment, 2026-10-09

Goal: reduce repeated compiler startup cost without weakening task quality, input
isolation, pin checks, failure stopping, or the existing model contract. This is a
small deterministic ontology/compiler experiment, not a general coding or model
benchmark. The old static pilot and PR14's 9/10 live run are separate evidence.

The hypothesis/reflection/comparison/refinement cycle is adapted from Google's
[AI co-scientist description](https://research.google/blog/accelerating-scientific-breakthroughs-with-an-ai-co-scientist/)
and [DeepMind overview](https://deepmind.google/blog/co-scientist-a-multi-agent-ai-partner-to-accelerate-research/).
The adoption gate here is executable independent reference checks and regression,
not model self-ratings. No additional research-agent or paid inference jobs ran.

## Hypotheses and falsification

1. Reusing at most three compiler requests avoids startup while rebuilding every
   artifact and reasoning snapshot. Refute if changed namespaces, Unicode labels,
   reordered or retracted data produce different receipts or ordinary results.
2. Parallel pin attestations reduce per-request overhead. All eight Git HEAD/status
   checks still run on each request; no attestation cache. The sequential worker is
   an ablation, preserving the same process reuse with old check ordering.
3. Batching three tasks avoids startup, but delays the first result and cannot stop
   between tasks. It remains a control; session duration is not divided by three
   and presented as per-task latency.
4. Exact known receipt caching is fast only after inputs were already compiled.
   Its prewarm cost is recorded separately and identity/pins checked before every
   serving request. It is not an unknown-input or model-generation improvement.

The selected policy is scoped process reuse plus parallel attestations, subject
to both development and holdout receipt equality, independent ordinary Todo
checks, fail-stop tests and the complete local CI recipe. Single task calls retain
the one-shot execution path. Mixed workflows retain their previous behavior.

## Frozen measurement conditions

`plan.json` is written before each experiment and includes all inputs and source
hashes. Three catalog repair/refactor tasks and three new boundary variants each
run three rounds across five policies (90 planned task observations per run).
Holdout uses new Japanese/emoji namespaces, non-BMP and combining string labels,
changed task keys and reversed state order. It is a separate boundary set from the
same task family, not a hidden/general benchmark. No candidate was tuned on its
outputs. Each before/after pair has eleven input snapshots. Full receipts match
fresh compilation; independent ordinary code verifies after-state behavior and
initial repair failure, or complete graph/result equality and size reduction for
refactors. Repeated observations are not independent unseen tasks.

Compiler commits and dependency pins are unchanged. Filesystem/dependencies are
warm, but each scoped process starts cold. First request and session startup are
included. Policy order rotates after the initial baseline-first round. First-run
Node unit regression briefly overlapped this shared Air experiment; the final
repeat has no intentional test overlap. Background OS load is uncontrolled.
macOS 26.3.1 (a), arm64; Node 24.21.0, npm 11.19.0, Python 3.12.12.

Stage rows record input assembly, pin verification plus compiler/runtime, and
independent feedback verification. Input task requirements and edit proposals
are already fixed, not generated by a model. Fresh requirement interpretation,
model generation, human review/repair time and invoiced costs are null/unmeasured.
Observed API calls/tokens are zero. No API keys are read or copied by the harness.
No LM Studio state/model installation is assumed or modified. Process inventory
was unavailable under sandbox permissions; that does not block this experiment.

The experiment cap is three requests per worker, three rounds, zero automatic
retries, and no paid inference. Stop on any mismatch/refusal and preserve recorded
rows and missing attempts. The final-code repeat after a close-race hardening
terminated without a diagnostic; its partial results remain separate. One
explicit new experiment checks the final code again. Exploration stops after
that repeat and local CI; do not keep searching to manufacture a 100x claim.

The active-process interruption probe deliberately has one interruption and one
missing next task, `complete:false`. Neither it nor the unexplained partial run
counts as an all-success benchmark. Compiler refusal also closes the worker,
with no restart or cached fallback. Regression tests cover close during attestation,
request/concurrency limits, started-process interruption and workflow quality.

## Remaining measurement and optional bounded follow-up

This experiment does not measure model proposal quality/latency, the API token
cost impact, human work, general coding throughput or an invoiced dollar saving.
No claim of 100x end-to-end improvement follows from cached or warm compiler rows.

A concrete optional next comparison is six new repair/refactor prompts, the same
approved available model in both policies, twelve calls total, no retries/cache,
maximum 4096 input tokens and 128 output tokens per call, and a separately approved
US$1 total ceiling. Model availability, tokenizer and provider prices must first
be verified; reject the run if worst-case advertised cost exceeds the ceiling or
cannot be bounded. Keep prompt/model/temperature and executable gates identical,
record model usage/latency and separate human-review timers, and retrieve actual
billing evidence before claiming dollar savings. This is a proposal only: it has
not been approved or executed and does not change any budget, credential or
permission. An existing confirmed free local model could instead be compared
without installation or spending, after coordination with its owner.
